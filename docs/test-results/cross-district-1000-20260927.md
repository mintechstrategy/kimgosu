# 강남구 일반인·영등포구 고수 1,000회 시나리오

- 실행일: 2026-09-27~28
- 실행기: `tests/cross_district_1000_scenarios.py`
- 데이터 식별자: `cross-district-20260927`
- 회차별 서비스·채팅방·메시지 ID: `cross-district-1000-20260927.json`
- 실행 대상: 로컬 PC Docker Compose의 기존 PostgreSQL

## 정상 흐름

강남구 거주 일반인 50명과 영등포구 거주 고수 50명을 번갈아 사용했다. 일반인 시작 500회, 고수 시작 500회에 모두 다음 순서를 적용했다.

1. 고수가 비대면 포트폴리오 서비스를 등록한다.
2. 일반인이 분야와 고유 검색어로 서비스를 찾고 상세를 연다.
3. 일반인이 문의하여 서비스와 독립된 채팅방을 만든다.
4. 고수가 응답한다.
5. 일반인과 고수가 초기 희망가, 시작가, 역제안가를 포함해 여섯 메시지를 주고받는다. 가격을 확정한 거래 데이터는 생성하지 않는다.

분야 7종, 최소 가격 19단계, 희망가·역제안가·희망일을 바꿨다. 두 지역이 달라 정상 흐름은 비대면 서비스로 구성했다.

## 비정상 흐름 10종

미인증 메시지, 비참여 일반인의 방 조회, 비참여 고수의 메시지, 본인 서비스 문의, 일반인의 서비스 등록, 대면 지역 누락, 존재하지 않는 분야, 타인 서비스 수정, 공백 메시지는 각각 거부 응답을 확인했다. 같은 이용자의 중복 문의는 새 방을 만들지 않고 기존 방을 반환했다.

이번 검증은 API·DB 테스트다. 실제 휴대폰 두 대의 UI·알림·네트워크 전환은 별도로 확인해야 한다.
