# 미결정 사항과 결정 기록

최종 갱신: 2026-09-27. 아래 질문은 **결정된 정책이 아니다**. 구현에 앞서 사용자와 정하고, 결정 시 이 문서의 기록에 옮긴다.

## 미결정 사항

| ID | 우선순위 | 질문 | 현재 근거·영향 |
|---|---|---|---|
| Q01 | 높음 | 고수 모드는 누구나 켤 수 있는가, 아니면 전문가 인증·승인이 필요한가? | 하나의 앱/UI 모드는 확정. 자격 검증은 화면에 정의되지 않음. 계정·서비스 등록 설계에 영향. |
| Q02 | 높음 | 소비자가 고수를 찾는 주 경로와 고수가 견적에 응답하는 주 경로를 MVP에서 모두 제공할 것인가? | 둘 다 화면에 있으나 고수 전용 화면 설계는 부족함. 내비게이션·개발 범위에 영향. |
| Q03 | 높음 | 견적 제안은 어떤 정보(가격·일정·메시지)를 포함하고, 수정·철회·수락·거절이 가능한가? | 화면에는 제안→채팅 연결만 확인됨. 제안 데이터와 상태 모델에 영향. |
| Q04 | 높음 | 거래 확정은 누가, 언제, 어떻게 하는가? 리뷰는 누구에게 언제 한 번 허용하는가? | D2–D3에 거래 여부/리뷰가 있으나 업무 규칙이 불명확함. 리뷰 신뢰성과 거래 모델에 영향. |
| Q05 | 높음 | MVP에 앱 내 결제·수수료·정산이 포함되는가? | 관련 화면 근거가 없음. 거래 상태와 운영 범위에 큰 영향. |
| Q06 | 중간 | 서비스와 견적의 공개·수정·숨김·마감·삭제 기준은 무엇인가? | 화면에 등록·관리 기능이 있으나 상태 전이가 불명확함. |
| Q07 | 중간 | 카테고리·지역·대면/비대면의 정합성, 검색/추천·정렬 기준은 무엇인가? | 탐색 화면은 있으나 데이터 운영·매칭 규칙이 부족함. |
| Q08 | 중간 | 신고·차단·분쟁·고객센터와 최소 운영자 기능은 무엇인가? | 화면에서는 MVP 관리자 범위가 정의되지 않음. 오남용 대응에 영향. |
| Q09 | 중간 | 탈퇴 시 상대방 채팅 보존, 개인정보 익명화/삭제, 보관 기간은 어떻게 할 것인가? | 탈퇴 문구와 상대방 대화 보존 간 충돌 가능. 데이터·정책 문구에 영향. |
| Q10 | 중간 | 알림은 어떤 사건에서 누구에게 가고, 중복·수신 설정·보관 기간은 어떻게 처리하는가? | 알림 화면은 있으나 사건별 정책이 불완전함. |
| Q11 | 중간 | 소비자/고수 전환 화면, 고수 홈·일감 탐색·제안 관리·성과 화면은 어떻게 구성하는가? | 제공된 자료는 주로 일반 소비자 화면. 고수 UI 설계가 필요함. |
| Q12 | 낮음 | 서비스 패키지·이미지·견적 입력 제한은 화면 문구를 그대로 채택할 것인가? | [API 초안](../API-SPEC.md)에 화면 기반 값과 설계 제안이 섞여 있어 최종 확인 필요. |
| Q13 | 중간 | 원본 서비스순서도에서 알림설정과 찜한 전문가에 중복된 `F4`의 고유 화면 ID를 어떻게 정할 것인가? | 구현 시 라우팅·분석 이벤트·문서 추적에 고유 ID 필요. [화면설계서](SCREEN-DESIGN.md)는 임시 표기 사용. |
| Q14 | 중간 | 검색에서 일치 카테고리가 없을 때 B2 추천을 선택하면 어디로 이동하는가? 로그인 후 최초 행동으로 어떻게 복귀하는가? | 서비스순서도에 후속 화살표와 복귀 규칙이 보이지 않음. |
