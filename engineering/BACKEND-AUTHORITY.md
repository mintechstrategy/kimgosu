# 백엔드 비즈니스 로직 정본 원칙

- 사용자 확정 기본 아키텍처 원칙. 최초 반영 작업: `KG-AUTH-INTEGRATION-02`.
- **규약 정본은 이 문서 한 곳**이다. AGENTS는 링크/핵심 원칙만, 기능별 API 계약은 구체적인 구현·버전·예외를 연결한다. 원칙 채택은 기존 코드 전체의 준수·QA 통과 또는 새 기능 구현을 뜻하지 않는다.
- 목적: 변경 가능한 사업정책을 가능한 한 백엔드 설정/배포와 호환 API로 변경하여 앱/웹의 정책계산·상수 복제로 인한 불일치와 앱 배포 의존을 줄인다. 모든 변경이 앱 배포 없이 가능하다고 약속하지 않는다.

## 1. 책임 경계

| 백엔드 최종 판단·집행 | 앱/웹 책임 |
|---|---|
| 인증/주체, 접근권한, 회원상태, 업무자격과 허용행동 | 서버 결과/오류의 정확한 표시, 접근 가능한 UI/상태/안내 |
| 금액·수수료·할인·견적/거래조건의 계산·검증과 확정 | 입력·미리보기 보조, 서버 확정 전 금액을 확정값으로 표시하지 않음 |
| 상태전이·기간/만료·유효제재·재가입·보존 기산 | 내비게이션, 원래 문맥 유지, 취소/복구·불확실 결과 안내 |
| 문서효력·동의/철회·현재 버전·필수/선택 분류 | 문서 열람/명시적 사용자 선택과 정확한 버전 전달 |
| 중복/재시도·동시성·트랜잭션·불변식·영속 저장 | 중복 탭 억제, 응답 후 재조회, 사용자 재확인; 서버 보장을 대체하지 않음 |
| 직접 API 요청에 대한 독립 재검증 | OS 권한/브라우저·기기 연동, Keychain/Keystore 등 보안 로컬저장 |

서버는 앱/웹에서 온 `status`, `customerNumber`, `canConsent`, `verified`, 금액/할인·자격·기산값을 권한의 증거로 신뢰하지 않는다. 세션/주체·저장된 사실·서버 시각·현재 정책·권한·허용된 상태전이를 다시 검증하고, server-generated 값은 server가 발급한다. 클라이언트가 입력한 사실/사용자 의사와 검증된 업무사실은 구분한다.

폼의 즉시 길이/형식 검사는 사용자 보조로 허용한다. 우회·오래된 클라이언트·임의 HTTP에도 같은 규칙이 서버에서 적용돼야 한다. 클라이언트 자체 계산으로 권한·가입/제재·보존/재가입 기산·문서효력·실제 금액을 확정하지 않는다. 서버의 부정/미준비/충돌 응답을 UI에서 성공으로 바꾸지 않는다.

## 2. 변경 가능한 정책값과 API 경계

- 정책값·제약·허용행동·기한/만료·정책/문서 버전은 **서버 설정 또는 서버 구현과 해당 API 응답**이 정본이다. UI의 문자열/정규식/카운터는 그 정본을 표시·보조할 뿐, 복제 상수로 최종 업무결정을 하지 않는다.
- 기능을 설계할 때 표시용 값/입력 제약과 서버 집행 규칙을 API에 분리하고, 응답의 의미·단위·필수/선택·미준비 상태·버전·캐시/갱신을 명세한다. `allowedActions`, policyRevision 같은 이름이 이 문서에 필요하다고 해서 기존 API에 이미 구현됐다고 간주하지 않는다.
- 변경 가능한 서버 설정은 승인된 값과 검증 범위 안에서만 사용한다. 설정화가 미구현이면 백엔드 코드/배포가 변경 수단이다. 운영자 화면·DB 직접변경·외부 발송·비용/법무 승인 권한을 새로 부여하지 않는다.
- 금액/견적 등 향후 도메인은 서버 계산/유효기간/버전/재확정 계약을 먼저 정의한다. 이번 회원작업은 해당 기능·DB 테이블·정산 기능을 추가하지 않는다.

## 3. 정책 변경·호환·문서·오래된 클라이언트

1. **승인과 효력**: 사업정책 값과 법률문서 승인/효력·중요변경/재동의 분류를 분리한다. 문서 kind/version/body hash/승인·시행 여부를 서버가 판단하고 필요한 사용자 선택과 함께 검증한다. 승인 전 DRAFT를 READY로 바꾸거나 OPERATIONS를 임의 필수 동의로 추가하지 않는다.
2. **호환 변경 우선**: 기존 method/path/필수 입출력 의미를 유지하고 추가 응답 metadata를 사용한다. 클라이언트는 미지 응답 필드를 무시하되, 판정에 필요한 필수 metadata 누락/타입오류를 성공으로 간주하지 않는다. 요청의 client-controlled 추가 필드는 기능별 스키마대로 거부한다.
3. **문서/정책 버전**: 선택 당시의 정확한 문서버전을 서버에 보낸다. 서버가 현재 효력버전과 대조해 충돌이면 갱신→표시→필요한 명시적 재확인으로 복구한다. 이전 문서의 동의를 새 버전에 복사하거나 재인증 후 이전 쓰기를 자동 재실행하지 않는다. 재동의 여부/제한업무 분류는 승인된 기준에 따라 API로 명세해야 하며, 아직 없는 분류 응답은 별도 미구현 게이트로 남긴다.
4. **캐시/재조회**: 현재 회원 API는 `Cache-Control:no-store`. 정책/권한 변화,409, 재진입·복원, 인증 갱신 뒤에는 관련 최신 문서/상태/허용행동을 다시 조회한다. 로컬 stale 값으로 서버 거절을 우회하지 않는다. 향후 캐시를 허용하면 policyRevision/ETag/갱신·무효화/민감정보 범위를 계약으로 먼저 정한다. 현재 ETag API가 있다고 주장하지 않는다.
5. **오래된 클라이언트**: 서버는 과거 client의 직접 요청도 최신 집행 규칙으로 재검증한다. 기존 호환 오류·미준비·버전충돌과 재조회로 안전하게 복구할 수 있으면 사용한다. 클라이언트가 새 필수 의미/표면/인증방식을 이해할 수 없으면 임의 기본값·성공 대신 호환 불가로 차단하고 별도 API 버전/명시적 업데이트 계약을 설계한다. 현재 source에 최소 앱버전·강제업데이트 endpoint가 구현됐다는 뜻은 아니다.
6. **배포의 한계**: 정상적·호환 가능한 정책값 변경은 가급적 서버 설정/백엔드 배포로 처리한다. 새로운 UI/OS 권한/플랫폼 기능, 앱 내장자산·입력 UX 변경, 서명/callback binding, 비호환 API 변경은 앱/웹 코드와 배포가 여전히 필요하다. 설정만으로 모든 클라이언트를 바꿀 수 있다고 보장하지 않는다.

## 4. 검증과 이행 — 원칙 반영 ≠ 기존 전체 준수

- 기능마다 서버 결정 지점·DB 불변식·클라이언트 보조규칙·정책값 전달 경로·실패/불확실 결과를 연결한다. 직접 API 우회·과거버전·중복·경쟁·stale 문서/시간·타인 ID/권한 입력을 부정 시험한다.
- 단위/로컬 더블, 실DB, 외부 제공사, 실제 앱/웹 거래, UIX QA·동등성의 증거를 분리한다. 문서 변경이나 green schema compile만으로 실제 집행을 입증하지 않는다.
- 위반·상수 중복·미구현이 발견되면 정확 source/라인·후보 hash·영향·수정 제안·미결정/승인 의존성을 반환하고, 범위가 승인된 **수정+대응 uiux 회귀 QA 세트**로 처리한다. 원칙 확정이 대규모 리팩터링·새 제품기능·법무/보관정책 결정·배포/비용/인증 변경의 자동 허가가 아니다.
- 회원 v0.2는 `contracts/auth-membership.v0.2.json`과 guide의 구체 현재 구현/제한을 따른다. 실제 회원 source는 서버 세션/문서/SMS/기산/CAS를 집행하지만, reconsent 분류·전체 allowed-action matrix·불확실 탈퇴 receipt·모든 클라이언트 정책상수 제거가 완료된 상태는 아니다.
- 이번 source 관측 예: Android `KGAuthModels.kt:74-76`, iOS `KGAuthModels.swift:91-93`에 phone/code/nickname 보조 정규식이 있고 web `domain.ts:9`, `App.vue:173`에 정책 안내값이 들어 있다. 현재 서버도 독립 재검증하고 외부 가입은 비활성이라 이를 곧바로 권한 우회 성공이라고 단정하지 않는다. 다만 값/문구가 바뀌면 client 표시가 낡을 수 있으므로 서버 메타데이터 기반 전달·갱신과 UIX 회귀의 후속 대상이다. 현재 동결 App/Web는 이 작업에서 수정하지 않았다.
- 독립 준수 감사자는 `engineering/business-logic-audit-01/**`에서 별도 판정한다. 통합 source/계약 동결 정본은 `engineering/auth-integration-02/CANDIDATE.json`이다. 원칙 문서 반영/로컬 기술 검증과 해당 감사 판정을 혼합하지 않는다.
